# 踩坑表

按"症状 → 原因 → 处理"组织。这些坑都是实际踩出来的，遇到相似现象先来这里对一遍。

## 音画不同步

**症状**：某个场景切过去时，听到的还是上一句；或者画面换了、人声慢半拍。

**原因与处理**：

1. **用"标点停顿 + 语速均分"推边界** —— 这是最常见的错误做法。TTS 的停顿和
   标点并不一一对应，场景内语速也会变，误差能到 0.3~1s。改用强制对齐（步骤 4）。
2. **锚点时间取字中心而不是字起始** —— whisper 常把单字拉长到 0.5~0.6s，
   用中心会让边界系统性偏晚 0.2~0.4s。必须用 `a + (b-a)*k/n`。
3. **ASR 输出繁体，与简体台本匹配断裂** —— 覆盖率会掉到 40% 以下，
   插值就退化成均分。先 `zhconv.convert(s, "zh-cn")`。
4. **把边界吸附到 RMS 静音段末尾** —— 软起音（s、x、q 开头）的 RMS 低于阈值，
   会被误判成静音，边界被推到人声中间。信首字时间，别信静音检测。
5. **字幕比画面早/晚** —— 字幕和场景边界必须用同一套锚点生成，不要一套用旧数据。

诊断工具：`check_sync.py`，它直接打印每个边界后 1 秒内的真实语音词。

## 录制

**症状**：合成后画面抖动、元素忽隐忽现。

**原因**：CSS 里残留了 `transition` / `animation`，或场景里用了 `setTimeout`。
逐帧截图时同一时刻可能截到过渡中间态，两帧之间状态不连续。
处理：全局禁用 transition，所有状态由 `render(t, d)` 直接赋值。

**症状**：首帧字体不对（用了 fallback 字体，字宽全变）。

**处理**：`record.py` 里已经 `await document.fonts.ready`；自定义字体要等
`document.fonts.load()` 完成再截。

**症状**：元素中心坐标算错，光标点偏。

**原因**：场景还是 `display:none` 时取了 `getBoundingClientRect()`，拿到全 0。
处理：`C()` 在尺寸为 0 时不缓存（模板里已处理）；或在 `seek` 里先切 `display` 再取坐标。

**症状**：Playwright 报找不到 chromium。

**处理**：`python -m playwright install chromium`。Node 版模块缺失时直接用 Python 版。

## 合成

**症状**：ffmpeg 报 `Unable to open ... ass`，成片没有字幕但也不报错。

**原因**：libass 对 Windows 带盘符的绝对路径解析不稳。
**处理**：`cd` 到字幕目录，只传文件名（`mux.py` 已内置）。

**症状**：成片比音频短一截。

**处理**：帧数 = `round(total * fps)`。`record.py` 已按这个算；手动改 fps 后要重录。

**症状**：字幕在浅色背景上看不清。

**处理**：深色字 + 白色描边（PrimaryColour 深、OutlineColour 白、Outline 3.2）。
纯白字在浅底上必然糊。

## 环境

**症状**：`huggingface.co` 连接超时 / 502。

**处理**：设 `HF_ENDPOINT=https://hf-mirror.com`，并 `HF_HUB_DISABLE_XET=1`
（xet 传输会去 cas-server 拿，镜像不支持，报 401）。

**症状**：faster-whisper 报 `open() got an unexpected keyword argument 'metadata_errors'`。

**原因**：新版 PyAV 与 faster-whisper 的调用签名不兼容。
**处理**：自己用 ffmpeg 解成 16k 单声道 float32 numpy 数组再传给 `transcribe()`
（`asr_words.py` 已内置）。

**症状**：没有 Gemini API Key，`tts_gemini.py` 报「缺少 API Key」。

**处理**：不要直接调 `tts_gemini.py`，用统一入口 `scripts/tts.py`。它按
`--api-key` / `GEMINI_API_KEY` / `GOOGLE_API_KEY` 判定，三者都没有就自动走本地
`edge-tts`（`pip install edge-tts`），后面所有步骤完全不变。也可 `--engine edge` 强制，
或 `--dry-run` 先确认会走哪条路。

**症状**：edge-tts 报 `NoAudioReceived` / 403 / 连接超时。

**处理**：edge-tts 是本地包，但**不是离线引擎**——合成请求要发到微软语音服务。
检查网络，必要时 `--proxy http://127.0.0.1:7897`；7.x 版靠 Sec-MS-GEC 校验，
系统时间偏差过大会 403，先校准系统时间。仍失败就 `--engine gemini` 并提供 Key。
完全离线时两条路都不通，人工提供 `voice.wav` 然后从步骤 3 继续。

**症状**：edge-tts 音色不合适 / 想换声线。

**处理**：`python -m edge_tts --list-voices`（CLI 不在 PATH 时这个最稳），用
`grep zh-CN`（Windows 用 `findstr zh-CN`）过滤；
常用 `zh-CN-YunxiNeural`（默认，男声讲解）、`zh-CN-XiaoxiaoNeural`（女声）、
`zh-CN-YunjianNeural`（沉稳解说）。用 `--voice` 传，`--rate +10%` 调语速比事后
`atempo` 拉快更自然。

**症状**：用 edge-tts 的 `--words` 时间戳跑 `align.py`，覆盖率反而低。

**处理**：`tts_edge.py` 已按 `1/ratio` 缩放 `--target` 变速后的词时间；若个别音色或
超长文案的边界元数据不准，回退到 `asr_words.py` 重新转写，别去改覆盖率阈值。

**症状**：Google API 连不上。

**处理**：用本地代理 `--proxy http://127.0.0.1:7897`。注意 query 参数传 key
（`?key=`）走代理会失败，必须用 header `x-goog-api-key`。不想折腾代理就直接
`--engine edge` 绕开 Google，无需 Key。

**症状**：后台跑录制，进程莫名消失。

**处理**：不要用 `&` / `nohup` 挂后台，用工具的后台任务机制，否则 shell 退出就被杀。

**症状**：批量删帧文件被安全策略拦截。

**处理**：不要删，换新目录名（`frames2` / `frames3`）。

## 内容

**症状**：字幕把英文单词切成两半（"Copilo" / "t"）。

**处理**：断句用宽度单位（汉字 1.0、ASCII 0.55）而不是字数，并把英文单词
整体作为一个 token（`align.py` 的 `split_subs` 已处理）。

**症状**：场景文本与文案差一个字。

**处理**：切分后立刻跑一次 `"".join(...) == 全文` 断言。标点错误（"，"写成"。"）
最隐蔽，肉眼看不出，但会让字幕时间整体错位。

**症状**：画面元素被按钮/卡片压住，或溢出舞台。

**处理**：内容区固定 712×600、底边不越 850；长文本先量宽度再决定字号，
不要指望浏览器自动缩。

## 图形

**症状**：等距图上的齿轮、表盘、圆形零件退化成一条线。

**原因**：等距投影写错——`sx = (xr - yr) * cos30` 会把 x 和 y 压到同一屏幕轴，
所有竖直面被压扁。
**处理**：标准等距是 `sx = xr * 1.2247`、`sy = yr * 0.7071 - z`、`depth = yr`。
`kit.js` 的 `Iso.prototype.p` 已按这个实现，不要自己另写一套。

**症状**：底板把管路、地脚、零件的下半截"吃掉"。

**原因**：大平面按"面平均深度"排序，深度落在画面中间，后面的小零件被整片盖住。
**处理**：地板/台面加 `ground:true`（内部 bias −9000），强制排到最底层。

**症状**：整台东西被切成几截，或零件前后关系在不同帧之间乱跳。

**原因**：按"面"排序而不是按"零件"排序。
**处理**：给每个零件 `part` 名和中心深度 `cd`，面的深度收敛到零件中心
（`cd + (d - cd) * 0.26`），再用 `bias` 做层内微调。

**症状**：重建 SVG 后，热点、提示气泡、角标都不见了。

**原因**：`host.innerHTML = ...` 清空了宿主里的其他子元素。
**处理**：重建前暂存非 `svg` 子元素，重建后 append 回去。

**症状**：聚焦某个零件后，整台机器像消失了。

**原因**：非聚焦部件透明度压到 0.2。
**处理**：压到 0.5 —— 既有层次，又不丢形。

**症状**：细节加得越多画面越脏。

**原因**：每个零件用了不同来源的色相/明度；或者光照方向不一致。
**处理**：所有颜色从 `K.palette(acc)` 派生，等距体块只走一套光源方向。

**症状**：一屏看起来"就几个方块"。

**原因**：图元数量不足，且缺"可测量的部分"。
**处理**：按 `scene-graphics.md` 第 4 节选母版；用循环补刻度/格栅/编号；
加接地阴影和一层 8~12% 的明度渐变。

**症状**：画面确实在动，但和旁白对不上。

**原因**：动效是临时想的，不是从旁白映射出来的。
**处理**：先写状态表（旁白片段 → 状态变量 → 变化区间），再写 `render`；
时间判断集中在 `state(t)` 开头，不要散落在绘图语句里。

**症状**：斜向排列的等距零件互相压住（三台机柜只看得见两台）。

**原因**：等距投影会沿一个轴压缩，世界坐标的间距到屏幕上会变小。
**处理**：等距里的间距按 1.6~1.8 倍给，排完抽一帧看，别按正视图的感觉排。
