# 图形与动效

这一章解决一件事：**怎么让画面"像那么回事"，而不是几个方块加箭头。**
适用于任何题材——机械装置、抽象架构、数据看板、界面操作、地图、剖面、时间轴。

代码工具在 `assets/stage/kit.js`，样张在 `assets/stage/kit-demo.html`
（浏览器直接打开，四块分别演示基础图元、数据图元、等距体块、组合场景）。
先打开样张看一眼再动手，比自己凭空想象快十倍。

---

## 1. 先诊断：为什么生成出来的图看着廉价

三种典型症状，对上任意一条就说明需要重做图形层，而不是"再加几个字"：

| 症状 | 具体表现 | 根因 |
|---|---|---|
| **只有几何，没有材质** | 纯色填充、均匀描边、没有光影、没有厚度 | 把图形当"示意符号"画，而不是当"物体"画 |
| **只有主体，没有环境** | 东西悬空、没有底面、没有刻度、没有标注 | 缺"可测量的部分"，观众无法判断尺度 |
| **只有状态，没有因果** | 画面一直在动，但动的东西和人说的话对不上 | 动效是装饰，不是旁白的映射 |

对应的三条对策，就是下面四条规则的前三条。

---

## 2. 四条硬规则

### R1 旁白里的每个名词，都要有专属形体

**不要**用一个方块换文字来表示"缓存 / 限流 / 引擎 / 管路"。
**要**让每个概念有各自的形状、各自的细节、各自的位置。

| 做法 | 结果 |
|---|---|
| 4 个一样的圆角矩形，文字不同 | 观众记不住谁是谁 |
| 罐（圆柱+液位）、阀（轮+杆）、齿轮（齿形+啮合）、管（三层描边+流向） | 说完一句，观众能在画面上指出对应的东西 |

判断标准：**关掉字幕，只看画面，能不能说出这一屏在讲什么。**

### R2 细节必须系统性生成，不能手摆

"精细"不是把坐标一个个敲进去，是用循环和参数生成：

```js
// 好：细节来自循环，改数量只改一个数字
for (var i = 0; i < 5; i++) {
  f.box(rx + 7, 139, 20 + i * 13, 32, 3, 6, [166, 188, 215], { part: "rack" });  // 散热格栅
}
// 坏：手写 5 组坐标，改一次要重排
```

细节的来源清单（都是循环几行就有的）：

- **等分刻度**：`c.ticks()` —— 长短交错 + 数字，立刻有"仪表感"
- **阵列元素**：铆钉、散热片、格栅、窗口、波纹、书架层板
- **重复结构**：管路的三层描边（暗底 + 亮心 + 高光）、卡片的两层描边
- **微小偏移**：同色系里 ±4% 的明度差，比纯色更"有材质"
- **接地与投影**：物体下面一圈椭圆阴影，解决"悬空感"

### R3 一套光源 + 一套色阶，否则越加细节越脏

只给一个主色 `acc`，所有颜色从 `K.palette(acc)` 里取：

```
主色 acc   → 派生出 accD(0.76) / accL(1.62) / accF(0.10)
中性四级   → ink / sub / weak / line
语义三色   → ok / warn / bad
```

等距体块用 `[r,g,b]` 数组 + 单一光源方向（默认左上前方），
**每加一个零件都走同一套光照**，画面自然统一。忘了这条，加十个细节就有十种风格。

### R4 状态即旁白：把"讲什么"写成 `t` 的函数

**这是最重要的一条，也是"关联上内容"的实现方式。**

不要给每个场景写一段独立的动画代码。给每个场景定义一组**状态变量**，
让它们随旁白推进而变，再用同一段渲染代码画出：

```js
var st = {
  level: K.key(t, [[0, 0.10], [3.2, 0.65]]),   // 液位：第 0 秒 10%，第 3.2 秒涨到 65%
  flow:  K.key(t, [[0, 0.20], [2.4, 0.85]]),   // 流速
  focus: t > 4.5 ? "valve" : "",               // 第 4.5 秒把镜头交给阀门
};
```

旁白说"令牌慢慢灌满桶" → `level` 从 0.1 涨到 0.9；
旁白说"阀门卡住了" → `valve` 在 0.3~0.5 之间来回抖；
旁白说"转速飙到 300" → `spin` 的斜率变陡。

**状态表**是这一步的产物，写在代码注释里，交付时一并对齐：

| 旁白片段 | 视觉主体 | 状态变量 | 变化 |
|---|---|---|---|
| "令牌按固定速率注入" | 阀门 + 管路 | `flow` | 0.2 → 0.85 |
| "桶满了就拒绝" | 液位 + 出口 | `level` | 涨到 0.9 后停住 |
| "这一层是瓶颈" | 服务节点 | `focus` | "svc"，其余压暗到 0.5 |

## 3. 从文案到画面：三步

### 3.1 抽名词 → 形体表

把这一屏的名词列出来，逐个分配形体。**名词少于 3 个的场景，说明文案还没拆细，
或者画面该做成"一个主体 + 一堆细节"（刻度、图例、读数）而不是多个并列物。**

### 3.2 抽动词/变化 → 状态变量

| 旁白里的词 | 对应的状态 |
|---|---|
| 增长 / 上涨 / 堆积 | `level`、`count`、柱高 |
| 流入 / 传递 / 下沉 | `flow`、路径 `p`、粒子位置 |
| 变快 / 加速 / 拥堵 | `spin`、`speed`、队列长度 |
| 聚焦 / 重点 / 问题在这 | `focus`、高亮、其余压暗 |
| 切换 / 变成 / 改为 | `mode`（枚举）、分段控件位置 |
| 删除 / 回退 / 收敛 | 反向 `p`、透明度下降 |

### 3.3 写状态表 → 写 `state(t)`

代码结构固定为三段：

```js
render: function (t, d) {
  var st = state(t, d);        // 1. 纯函数：t -> 状态（全部 if/插值都在这里）
  paint(st);                   // 2. 画：只读状态，不判断时间
}
```

好处：改节奏只动 `state()`；改外观只动 `paint()`；两者不会互相污染。

## 4. 五种构图母版

选一个母版，不要混。混了就会乱。

### M1 装置 / 器物（等距体块）

**适用**：机械、硬件、实体产品、容器、分层结构、货架、数据立方。
**实现**：`K.iso()` + `box / prism / cyl / pipe`。
**栅格**：主图占内容区 60~70% 宽，标签放右侧一列（不压在图上）。
**必备零件**：底板（`ground:true`）、接地阴影、2~3 处细节阵列、2~4 条引导线标签。
**状态变量**：`yaw`（旋转）、`level`（容器充填）、`flow`（管路流动）、`spin`（转动件）、`focus`。
**失败长这样**：零件全飘在空中、底板把管子吃掉、所有面一样亮。

### M2 流程 / 架构（节点 + 正交连线）

**适用**：系统架构、业务流程、数据管道、决策树、调用链。
**实现**：`c.node()` + `c.edge()`。
**栅格**：横向 3~5 个节点，间距 ≥ 40px；纵向分层时每层高 90~130px。
**必备零件**：节点图标、端口小圆点、连线箭头、路径上的流动点、一个高亮节点。
**状态变量**：`p`（连线生长 0→1）、`active`（当前节点）、`flow`（数据点移动）。
**失败长这样**：箭头穿过文字、连线斜着乱飞、所有节点一样大。

### M3 数据 / 指标（图表矩阵）

**适用**：增长、占比、对比、趋势、成本、性能。
**实现**：`c.bars()` / `c.lineChart()` / `c.donut()` + KPI 卡片 + `c.ticks()`。
**栅格**：上行 3 个 KPI（每个 160×74），中行图表（左柱右线），下行结论条。
**必备零件**：坐标轴、网格虚线、单位、同比箭头、结论条（一句人话）。
**状态变量**：`p`（柱高/折线延伸）、`hl`（重点柱）、计数。
**失败长这样**：没有坐标轴、数字加不上、图和文案口径不一致。

### M4 界面 / 操作（窗口 + 光标）

**适用**：软件演示、SaaS、App、后台、编辑器。
**实现**：HTML 元素（沿用 `styles.css` 的 `.card/.btn`）+ `c` 只画示意小图。
**栅格**：窗口 712×460，左栏 180，主区其余；工具栏 h 44。
**必备零件**：标题栏三点、工具栏图标、输入框光标、状态徽标、滚动条、真实鼠标轨迹。
**状态变量**：输入进度（`typeInto`）、菜单展开、选中行、点击涟漪。
**失败长这样**：窗口是纯白矩形、按钮没有按下态、光标不落在它点的位置上。

### M5 空间 / 层级（地图、剖面、时间轴、树）

**适用**：地理、历史、组织结构、目录树、演进阶段。
**实现**：`prism` 挤出板块（地图）、`ticks` + 区间条（时间轴）、缩进卡片（树）。
**必备零件**：边界/刻度、比例尺或年份、当前项游标、已发生/未发生两态。
**状态变量**：游标位置、区域点亮、分支展开度。
**失败长这样**：地图是几个色块、时间轴没有刻度、树没有层级缩进。

## 5. 图元与细节词汇表

按"要解决的问题"查，不要按名字查。

| 需要 | 用什么 | 备注 |
|---|---|---|
| 一块有厚度的地面 | `f.box(..., {ground:true})` | 不加 `ground` 会盖住远处的零件 |
| 悬空感 | `f.shadow(cx,cy,rx,ry)` | 椭圆投影，深度设为最低 |
| 圆柱 / 罐 / 柱状图立体化 | `f.cyl(cx,cy,z0,z1,r,rgb,{n:22})` | n 越大越圆，22 够用 |
| 齿形 / 异形 / 地图板块 | `f.prism(profile2D, z0, z1, rgb)` | 任意 2D 轮廓挤出，最通用 |
| 管路 / 线缆 / 轨道 | `f.pipe(pts, r, {acc})` | 四层描边，自带流动虚线 |
| 法兰 / 垫圈 / 轨道圈 | `f.ring(cx,cy,z,r)` | |
| 把标签钉在 3D 物件上 | `f.screen(x,y,z)` → `c.callout()` | 不要手算偏移 |
| 卡片 / 面板 | `c.card()` | 白底 + 细边 + 投影 + 可选 `glow` |
| 流程节点 | `c.node()` | 自动按文字撑高，`active` 带左侧色条 |
| 正交连线 | `c.edge({route:'auto'})` | 自动选横/竖/曲线，带箭头与 `p` 生长 |
| 引线标签 | `c.callout()` | 短虚线 + 端点小圆 |
| 刻度 | `c.ticks({baseline:true})` | 长短交错，`label(i)` 给数字 |
| 柱状 / 折线 / 环 | `c.bars` / `c.lineChart` / `c.donut` | 都吃 `p`，天然可动画 |
| 状态标签 | `c.pill()` | 胶囊底 + 文字，返回宽度便于横向排布 |
| 纹理 / 噪点 | `K.rng(seed)` + 循环 | 同一 seed 每帧一致，不会抖 |

## 6. kit.js API

引入顺序：`kit.js` 在 `engine.js` 之前。

```html
<script src="timeline.js"></script>
<script src="kit.js"></script>
<script src="engine.js"></script>
<script src="scenes.js"></script>
```

### 画布

```js
var c = K.canvas(712, 600, { acc: "#2563eb" });   // 尺寸用内容区尺寸
c.rect({ x, y, w, h, r, fill, stroke, sw, dash, op, shadow, layer, z });
c.card({ x, y, w, h, r, glow });                   // 卡片（自带投影）
c.circle({ x, y, r, fill });  c.ellipse({ x, y, rx, ry });
c.poly({ pts: [[x,y],...], closed: false });       // closed:false 画折线
c.line({ pts, stroke, sw, dash });
c.text({ x, y, s, size, weight, fill, anchor, lh, ls });
   // s 可以是数组：每项一行；y 是基线
c.pill({ x, y, s })            → 返回宽度
c.accent({ x, y, w, h, r })    // 卡片左侧强调条：短竖条 + 圆角端头，自动让开圆角
c.node({ x, y, w, title, body, icon, active })   → 返回高度
c.edge({ from:[x,y], to:[x,y], p, color, label, route:"auto"|"h"|"v"|"curve"|"straight" })
c.callout({ x, y, s, to:[x,y] })
c.bars({ x, y, w, h, p, data:[{k, v, hl}] })
c.lineChart({ x, y, w, h, p, series:[{pts:[...], color, area}], xs:[...] })
c.donut({ x, y, r, sw, p, s:"72%", sub:"命中率" })
c.ticks({ x, y, w, n, major, baseline:true, label:i=>i*20 })
c.raw("<g>…</g>", { layer });
c.svg();  c.mount("slot");
c.layer("annot", function (c) { /* 这一组都画在标注层 */ });
```

排版对齐的四条约定（不守这几条，画面就会"歪"）：

- `node()` 有 `icon` 时，正文与标题共用同一条左基准线（`padX + 29`），不要自己再挪正文；
- 显式给 `node(..., h)` 时内容垂直居中；不给则按文字自动撑高，两种都不会顶部堆字；
- `edge({label})` 的标签自动落在线的侧面（竖线在右、横线在上），不要再手加 `labelDy` 去躲线；
- `callout()` 的引线自动接到离目标最近的那条边，标签放哪一侧由 `x` 决定，不要靠推算。

**分层**：`bg < struct < content < fx < annot`，同层按 `z` 排。标注永远在最上面，
避免引线被图形盖住。坐标原点在内容区左上角，不是页面左上角。

### 等距体块

```js
var f = K.iso({ yaw: 42, cx: 150, cy: 105 });     // cx/cy 是旋转中心（世界坐标）
f.box(x, y, z, w, d, h, [r,g,b], { part:"rack", ground:true, noBottom:true });
f.prism([[x,y],...], z0, z1, [r,g,b], { noTop:true });
f.cyl(cx, cy, z0, z1, r, [r,g,b], { n:22 });
f.pipe([[x,y,z],...], r, { acc:"#2563eb", part:"pipe" });
f.ring(cx, cy, z, r, { col:"#9ebfe2", w:2.6 });
f.shadow(cx, cy, rx, ry);
f.flush(c, { x: 0, y: 0, w: 712, h: 420 });       // 自动缩放居中 + 排序输出
f.screen(x, y, z);                                // flush 之后：世界坐标 → 画布坐标
```

- `part` 是分组名，写进 `data-p`，供 `K.focus(root, "valve")` 做聚焦压暗。
- `ground:true` 只给地板/台面用。**不加会出的事**：大平面按平均深度排序时
  会盖住远处的管路和小零件（症状是"管子凭空消失"）。
- `yaw` 改变会重建整棵几何，成本高。只在需要"真的转动"的场景用，
  其余场景固定 40~45°，靠 `level/flow/spin/focus` 变化就够了。

**重建与补丁**：一屏几百个面时，每帧重新 `flush()` 会明显拖慢录制。
正确做法是只在"结构真的变了"时重建，其余帧改属性：

```js
var host = document.getElementById("mach");
var key = yaw.toFixed(1) + acc;
if (host.__key !== key) {                  // 只有转角/主色变才重建
  host.__key = key;
  var c = K.canvas(420, 400, { acc: acc });
  var f = K.iso({ yaw: yaw });
  /* …build… */
  f.flush(c, { x: 0, y: 0, w: 420, h: 400 });
  host.__f = f;
  var keep = [].filter.call(host.children, function (n) { return !n.matches("svg"); });
  host.innerHTML = c.svg();
  keep.forEach(function (n) { host.appendChild(n); });   // 热点/提示等子元素要留住
}
K.focus(host, focusPart);
K.spin(host, "gearA", spin);
K.flow(host, t * 30);
```

两条坑：

- `host.innerHTML = ...` 会清掉宿主里原有的热点、提示气泡，**先暂存再插回**；
- 聚焦时把非目标压到 0.2 会让整台东西"消失"，`K.focus` 用 0.5，既有层次又不失真。

### 时间与动画

```js
K.key(t, [[0, 0.2], [3, 0.9]])     // 关键帧插值（默认 easeOut）
K.seq(t, i, start, gap, dur)       // 第 i 个元素的错峰入场 0→1
K.win(t, a, b)                     // 夹紧的线性进度
K.ease / K.easeOut / K.easeIn / K.lerp / K.clamp

K.flow(root, t, speed)             // 让 data-k="flow" 的描边流动
K.spin(root, key, deg)             // 让带 data-cx/cy 的元素绕自身中心旋转
K.focus(root, "valve")             // 非聚焦零件压暗到 0.5
K.num(el, v, {dec, suffix})        // 数字滚动
K.pulse(root, key, t)              // 呼吸（强调"正在运行"）
```

`root` 传宿主元素，不传就是整个 document。这些函数只改属性，不改结构，
所以逐帧调用很便宜。

### 完整示例：一屏从状态到画面

`index.html` 里放一个宿主 `<div id="slot" style="position:absolute;left:0;top:330px;width:712px;height:270px"></div>`，
`scenes.js` 里：

```js
render: function (t, d) {
  var p = K.key(t, [[0.6, 0], [2.6, 1]]);          // 主线进度：旁白说到第 2 句时图长完
  var c = K.canvas(712, 270, { acc: "#2563eb" });   // 尺寸 = 宿主尺寸，坐标原点就是宿主左上角

  c.text({ x: 4, y: 20, s: "三个环节的耗时占比", size: 15, weight: 700, fill: "ink" });

  var N = [["接入", 18], ["处理", 260], ["落库", 74]];
  N.forEach(function (n, i) {
    var x = 6 + i * 236;
    c.node({ x: x, y: 40, w: 200, h: 66, icon: "◆",
      title: n[0], body: "占 " + Math.round(n[1] / 3.52) + "%",
      active: i === 1 && p > 0.5,                     // 旁白讲到"处理"时高亮
      op: K.seq(t, i, 0.6, 0.15, 0.4) });             // 错峰入场
    if (i < 2) c.edge({ from: [x + 200, 73], to: [x + 236, 73], p: p, color: "acc" });
  });

  c.bars({ x: 6, y: 130, w: 420, h: 110, p: p,
    data: N.map(function (n) { return { k: n[0], v: n[1], hl: n[1] > 200 }; }) });

  c.ticks({ x: 460, y: 230, w: 240, n: 8, major: 2, baseline: true,
    label: function (i) { return i * 50 + "ms"; } });

  c.callout({ x: 470, y: 150, s: "瓶颈在这里", to: [300, 168] });

  c.mount("slot");
}
```

要点：

- 整个函数没有一处 `if (t > ...)` 散落在绘图语句里，时间判断全在开头几行算成状态；
- `p` 同时驱动连线生长、柱高、节点高亮，三者天然同步；
- 宿主尺寸写死在 `K.canvas()` 里，`mount()` 不会改变布局，所以可以反复逐帧调用；
- 每帧重建字符串有成本，一屏 100 个图元约 1~2ms，25fps 下完全够用；
  只有等距体块（几百个面）在 `yaw` 变化时才需要特殊处理。

---

## 7. 动画动词表

画面在动 ≠ 有动效。每种"动作"要对应一种"意思"，否则就是噪声。

| 动词 | 观感 | 实现 | 时长 |
|---|---|---|---|
| 生长 | 从无到有 | `p` 0→1（描边 `pathLength`、柱高、节点 `op`） | 0.3~0.6s |
| 流动 | 内部在传送 | `stroke-dashoffset` + `K.flow` | 持续 |
| 充填 | 累积、变满 | 容器内液位高度随 `level` | 1.5~3s |
| 旋转 | 运转中 | `K.spin`，转速要变（加速比匀速有信息量） | 持续 |
| 脉冲 | 心跳、告警 | 透明度 0.6~1 正弦 | 周期 0.8s |
| 聚焦 | "注意这里" | 目标不变 + 其余 `opacity` ×0.5 | 0.25s |
| 擦除 | 替换、旧版消失 | 新图层 `clip` 从左推进 | 0.4s |
| 计数 | 数字有意义 | 从 0 滚到目标值，`easeOut` 收尾 | 0.8~1.5s |
| 弹入 | 出现很重要 | `translateY(12px)` + `scale(.96)` → 1 | 0.3s |
| 扫描 | 检测、遍历 | 一条半透明竖线横扫 + 经过处高亮 | 0.8s |

**节奏**：同一屏不要超过 3 种动词同时进行。多了一定乱。

---

## 8. 施工顺序

不要一上来就画细节，会返工。

1. **骨架**：先用灰块占位，确认每个东西的位置和大小（5 分钟）
2. **悬停检查**：抽 2~3 帧看有没有重叠、溢出、比例失衡（这一步省掉，后面全白做）
3. **材质**：统一色阶、加投影、加边缘描边
4. **细节**：循环加刻度/格栅/铆钉/纹理
5. **标注**：引导线标签、图例、单位
6. **状态**：接上 `state(t)`，逐帧看一遍状态变化是否跟得上旁白
7. **收尾**：最后 0.45s 不再新增元素

## 9. 反模式

| 反模式 | 为什么不行 | 改成 |
|---|---|---|
| 所有元素同一个圆角矩形 | 没有辨识度 | 按语义分类：容器用圆/柱，流程用直角卡，数据用条形 |
| 纯色大色块 | 廉价、没有材质 | 加 8~12% 的明度渐变、边缘 1px 亮线 |
| 线条粗细全一样 | 没有主次 | 主结构 2.5~3，次结构 1~1.5，装饰 0.8 |
| 图标用 emoji | 跨平台渲染不一致，风格跳 | 用几何图形或单个字符（◍ ⚙ ≋ ⇄ ◇） |
| 一屏塞 3 个不同的图 | 观众不知道看哪 | 一个主图 + 一组读数 |
| 装饰性粒子/光斑 | 和内容无关，纯噪声 | 删掉，或换成有物理含义的流动 |
| 运动幅度太大 | 看久了晕 | 位移 ≤ 20px，缩放 0.94~1.06 |
| 数字四舍五入后加不上 | 观众一算就发现 | 写死底数，百分数按最大余数法分配 |

## 10. 验收

### 静帧测试（必做）

关掉字幕、关掉声音，只看画面。逐屏问三句：

1. 这屏在讲什么？（说不出 → 形体没区分度）
2. 哪里是重点？（看不出 → 缺聚焦/对比）
3. 有没有"可以量的东西"？（没有 → 缺刻度、读数、坐标轴）

### 细节计数（可选，但很有效）

```js
// 在浏览器控制台里，看这一屏到底有多少图元
document.querySelectorAll("#sc7 *").length;   // 目标 40~120
```

低于 40 通常是"几个方块"；高于 150 通常信息过载，要拆场景。

### 一致性检查

- 所有颜色都能从 `K.palette(acc)` 里找到出处，没有孤立的手写色值
- 所有数字与旁白口径一致，合计真的加得上
- 同一屏里的同类元素，圆角、描边、字号一致
- 每屏至少 3 种交互元素（沿用 `design-rules.md` 的要求）
- 光标/高亮落在它真正指向的元素上
